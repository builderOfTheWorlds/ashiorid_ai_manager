================================================================================
                   DATA-PREP SERVICE - QUICK REFERENCE
================================================================================

CURRENT STATE:
- NO dedicated data-prep-service exists
- File processing is integrated into lore-rag-service (Port 8002)
- Currently supports: TXT, MD files only
- Branch: claude/add-pdf-support-011CUv7gG3KGUsgUQVA3QLUB

================================================================================
SUPPORTED FILE TYPES
================================================================================

Current:
  - .txt (plain text)
  - .md (markdown)

NOT YET SUPPORTED:
  - .pdf (requires PDF parser)
  - .docx
  - Other binary formats

File Size Limit: 50 MB (configurable)

================================================================================
KEY COMPONENTS & ENTRY POINTS
================================================================================

1. FILE UPLOAD HANDLER
   Location: lore-rag-service/src/api/routes.py (lines 153-201)
   Function: ingest_file()
   Input: UploadFile
   Output: JSON status response
   
   LIMITATION: Only UTF-8 decoding, cannot parse PDFs

2. INGESTION SERVICE
   Location: lore-rag-service/src/services/ingestion.py
   Classes:
     - IngestionService: Main processing pipeline
   
   Key Methods:
     - ingest_text(text, source, collection)     → Processes raw text
     - _chunk_text(text, source)                  → Splits into chunks
     - ingest(documents, collection)              → Stores in Qdrant

3. TEXT CHUNKING
   Strategy: Token-based chunking
   Library: tiktoken
   Parameters:
     - chunk_size: 512 tokens
     - overlap: 50 tokens
     - min_chunk_size: 100 tokens

4. EMBEDDING GENERATION
   Location: lore-rag-service/src/services/embeddings.py
   Service: Ollama
   Model: nomic-embed-text (768 dimensions)
   Batch Size: 32 texts per batch

5. VECTOR STORAGE
   Location: lore-rag-service/src/services/qdrant_client.py
   Database: Qdrant
   Storage Format: PointStruct with payload
   Payload Contains:
     - text: chunk content
     - source: file identifier
     - metadata: custom key-value pairs

================================================================================
PROCESSING PIPELINE
================================================================================

Upload File
    ↓
Detect File Type (routes.py)
    ↓
Parse File → Extract Text (MISSING FOR PDF)
    ↓
Chunk Text (token-based, 512 tokens)
    ↓
Generate Embeddings (Ollama API)
    ↓
Create Qdrant Points (PointStruct)
    ↓
Upsert to Qdrant Vector DB
    ↓
Return: {status, filename, collection, chunks_created}

================================================================================
OUTPUT FORMATS
================================================================================

INGESTION RESPONSE:
{
    "status": "success",
    "filename": "document.txt",
    "collection": "lore",
    "chunks_created": 42,
    "details": {
        "documents_ingested": 42,
        "embeddings_generated": 42,
        "points_upserted": 42
    }
}

STORED IN QDRANT:
PointStruct {
    id: "uuid-string",
    vector: [768 floats],  # embedding
    payload: {
        "text": "chunk text...",
        "source": "filename.txt",
        "metadata": {
            "chunk_index": 0,
            "token_count": 512
        }
    }
}

SEARCH RESULT:
{
    "text": "chunk text...",
    "score": 0.92,           # similarity (0-1)
    "source": "filename.txt",
    "metadata": {...}
}
